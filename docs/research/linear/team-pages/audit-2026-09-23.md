### 共享 shell 事实（三页通用，避免重复列）

- 单路由 `/teams/:teamId` + `?tab=` 切换五面（`desktopRouter.shared.tsx:819-827`；`TeamPage.tsx:255`）。query-param 方案 spec 已认可，不要求改成 Linear 路径形态。

- `teamData` 抓取是三页共同闸门：失败 → 整面 `AsyncError`（`:604-605`），加载中页头回落 `t('tab.teams')`。
- 侧栏子导航 5 项默认展开、`triageEnabled===false` 时隐藏 Triage 项（`TeamsSection.tsx:65-71,202-205`；`useTeamSubNav.ts` 持久化「折叠集」而非「展开集」——PARITY-MATRIX 里「默认折叠」一行已过时）。
- `?tab=` 取非法值时所有分支都不渲染 → 页头下空白，无回落（源码，边角）。
- 列表数据通道统一 `workAttentionService.query`，默认 `limit=50`（`workAttention.ts` router `:415`）。
- **新发现（缺陷）**：`act()`/`refreshTriage()` 里 `mutate(['team-tasks', workspaceId, teamId, cycleId, noProject, layout, issueScope])`（`TeamPage.tsx:388-389,406-409`）缺订阅 key 的第 8 位 `triageCapable`（订阅见 `:300`）。SWR 数组 key 精确匹配 → **分诊动作与看板拖动后的 team-tasks 重验证静默落空**，Issues 面陈旧到下一次自然 revalidate。triage key（5 元素）能命中。

## 关键结论速览

1. **三页均未达 parity**。Issues 语义层（查询谓词 /scope 历史）已修且有运行时证据，chrome 层（页头 / Add filter/Display options / 详情板 /saved view 入口）全缺；Projects 仍是非目标形态的紧凑行；Triage 创建绑定已修但 populated 语义两端都无证据。
2. **两条源码级新缺陷**（本审计首次记录，未在任何 spec 中）：team-tasks `mutate` key 缺 `triageCapable` → 分诊动作 / 看板拖动后 issues 面不刷新；看板 `onCreate` 门对 `wf:*` 列键恒假 → team 看板创建入口整体缺失。
3. **两条语义泄漏风险**：untriaged 任务默认 `workflowCategory='backlog'` 且无 `triageStatus` 排除谓词 → 漏进 All/Backlog；`wf:triage` 列常驻看板。
4. **阻塞项**：Triage populated 参考端采集（T4）；Projects 复用工作区表前的 `taskCount`/`progressPercent` 富化（P6）与在途 owner 对齐。
