# OAuth 连接现在会收敛到明确的终态

连接 GitHub、自定义 MCP 连接器或 Linear 工作区时，界面可能一直转圈：两分钟计时器只是停止轮询，关闭弹窗有时让按钮卡在 “连接中”，迟到或外来的结果消息还可能错误地结算到别的尝试。现在所有授权流程共用同一套会话协议：明确的终态、按尝试关联身份、以及丢消息时的服务端状态回查。

## 修复

- \*\* 超时真正结束等待。\*\* 授权截止时间一到，连接按钮退出 “连接中”，显示超时提示，并变为 “检查状态”/ 重试动作。此前 GitHub 流程只清理了轮询定时器，可能无限卡在连接中。
- \*\* 结果与本次尝试绑定。\*\* 每次授权都会生成一个 nonce，经由 start 调用、服务端 OAuth 状态与回调 postMessage 回传。缺少该 nonce 的消息 —— 上一次尝试的过期结果或外来的 postMessage—— 都会被忽略，而不是错误结算会话。
- \*\* 丢消息不再等于丢授权。\*\* 当结果 postMessage 未到达（弹窗提前关闭或超时），应用会先向服务端确认授权是否真的完成，再判定失败，已完成的连接依然生效。
- \*\* 统一的会话协议。\*\*GitHub 连接器、自定义连接器弹窗、添加连接器弹窗以及 Linear 工作区安装 / 导入流程现在都使用同一个一次性结算的 helper，带弹窗来源校验、取消支持与监听器 / 定时器清理 —— 重复实现的弹窗代码已移除。
