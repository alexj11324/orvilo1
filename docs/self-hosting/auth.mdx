# Authentication Service

Orvilo delegates sign-in to a dedicated **accounts portal** powered by [Clerk](https://clerk.com). The portal owns the Clerk session; the Orvilo app exchanges the Clerk session token for its own `orvilo_auth` session cookie backed by the `auth_sessions` table.

## How It Works

1. An unauthenticated user hitting Orvilo is redirected to the accounts portal (`AUTH_ACCOUNTS_URL`, e.g. `https://accounts.aspectlylabs.com`).
2. The user signs in with Clerk (email/password, magic link, OAuth — whichever methods the Clerk instance enables).
3. After sign-in the portal calls the app's `POST /api/auth/clerk` endpoint with the Clerk session token; the app verifies the token signature and issuer, checks the session and user against the Clerk Backend API, then issues the `orvilo_auth` cookie.
4. The same portal flow also powers desktop and CLI authorization through Orvilo's built-in OIDC provider (`/oidc/*` endpoints).

## Environment Variables

| Environment Variable       | Type     | Description                                                                                           |
| -------------------------- | -------- | ----------------------------------------------------------------------------------------------------- |
| `AUTH_ACCOUNTS_URL`        | Required | Origin of the accounts portal sign-in page (e.g. `https://accounts.aspectlylabs.com`).                |
| `CLERK_SECRET_KEY`         | Required | Clerk Backend API secret key (`sk_*`) — used to validate sessions and provision users on first login. |
| `CLERK_ISSUER`             | Optional | Clerk issuer / frontend API origin (e.g. `https://clerk.aspectlylabs.com`).                           |
| `CLERK_AUTHORIZED_PARTIES` | Optional | Comma-separated `azp` allowlist for session token exchange.                                           |
| `CLERK_JWT_KEY`            | Optional | PEM public key for fully offline session-JWT verification (skips JWKS fetch).                         |
| `AUTH_COOKIE_DOMAIN`       | Optional | Parent domain for the session cookie (e.g. `.aspectlylabs.com`) so the portal and app share auth.     |
| `AUTH_SESSION_TTL_SECONDS` | Optional | App session lifetime in seconds (default 30 days).                                                    |

See [Authentication environment variables](/docs/self-hosting/environment-variables/auth) for the full reference.

## Sign-In Methods

Email/password, magic link, OAuth providers, and MFA are configured in the Clerk dashboard backing the accounts portal — not in Orvilo env vars. Feature flags forwarded to the portal:

| Environment Variable          | Description                                              |
| ----------------------------- | -------------------------------------------------------- |
| `AUTH_DISABLE_EMAIL_PASSWORD` | Hide the email/password form on the portal sign-in page. |
| `AUTH_ENABLE_MAGIC_LINK`      | Enable magic-link sign-in on the portal.                 |
| `AUTH_EMAIL_VERIFICATION`     | Require email verification on the portal.                |

## Legacy Notes

- Earlier Orvilo versions used Better Auth. The library and its `/api/auth/*` endpoints have been removed; sessions issued by it (`<prefix>.session_token` cookies) are still honored until they expire, then users re-sign in via the portal.
- Better Auth–era tables (`account`, `auth_sessions` legacy rows, etc.) are left in place for data retention.
