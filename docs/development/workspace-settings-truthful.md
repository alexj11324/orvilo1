# Workspace settings: stop lying about scope

An audit of the workspace settings sidebar found controls that claimed a
workspace scope they did not have, or did nothing. This change removes or
corrects them. Front-end only.

## What changed

| Item                        | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Evidence                                                                                                                                                           |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Workspace 服务模型 / 服务商 | Sidebar entries, workspace leaves and the `WorkspaceAdminOnly` wrapper removed. `/:slug/settings/service-model` and `/:slug/settings/provider` are `WORKSPACE_SETTINGS_ALIASES` entries with an absolute target (`/settings/service-model`, `/settings/provider`); `provider/:providerId` keeps the id via `WorkspaceProviderRedirect`. `provider` / `service-model` dropped from `WORKSPACE_SETTINGS_TABS` so personal links are no longer rewritten onto a workspace path. | The pages wrote the caller's personal settings (`store/user/slices/settings/action.ts` → `userService.updateUserSettings`); provider bindings are always personal. |
| Workspace 通知              | Nav entry and route gated by `isWorkspaceSettingsTabAvailable` (needs `enableBusinessFeatures`). The business page is untouched. Unlike the personal tab there is no desktop exception: the desktop page is a local OS-notification page, the workspace tab is always the business component.                                                                                                                                                                                | Nothing outside the business page reads `workspace_user_settings.notification`.                                                                                    |
| Members → 智能体            | Removed the hard-coded "可使用 ✓" / "不可编辑 –" columns and their locale keys.                                                                                                                                                                                                                                                                                                                                                                                              | Rendered unconditionally for every row.                                                                                                                            |
| Business tabs by URL        | Plans, Usage, Credits, Budget, Billing and Notification leaves are wrapped in `WorkspaceSettingsTabGate`; with the flag off a direct URL redirects to the workspace settings root, like an unknown tab. Decision lives in `isWorkspaceSettingsTabAvailable` (`packages/app-config/src/routes/settings.ts`). Routes and pages are kept as the overlay injection points.                                                                                                       |                                                                                                                                                                    |
| 概览                        | The sidebar label (and the shared page heading key `workspaceSetting.tab.general`) now reads Overview / 概览.                                                                                                                                                                                                                                                                                                                                                                |                                                                                                                                                                    |
| Imports                     | Moved from the Agent group to the Workspace group.                                                                                                                                                                                                                                                                                                                                                                                                                           | Importing is workspace data management.                                                                                                                            |

## Left for backend / business package

- `workspace.update` is not implemented, so Overview is read-only.
- No reader exists for `workspace_user_settings.notification`; the workspace
  notification switches stay hidden until one does.
- `src/business/client/BusinessSettingPages/WorkspaceGeneral.tsx` still formats
  the created date as `MMM D, YYYY`; it should render `YYYY/MM/DD`. It lives in
  the business overlay, so it was not edited here.
