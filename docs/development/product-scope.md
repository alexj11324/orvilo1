# Orvilo 产品边界

> 本文件声明 Orvilo 的长期产品边界，以及**不得重新引入**的功能形态。
> 执行记录与各工作包状态见 [task-first-rollout.md](./task-first-rollout.md)。

## 一句话定位

类似 Linear、以任务看板为中心、Agent 作为执行者的任务管理应用。

任务是工作记录；项目组织工作；Agent 执行工作；对话用于协作；资料提供上下文；产物与证据用于验收。

## 边界原则

> **删除平行的产品形态，不删除执行任务所需的基础能力。**

「不再提供独立图片创作中心」与「Agent 不能生成图片」是两个完全不同的决定。
退役一个入口时，必须逐条追踪 `导航/快捷键/命令 → 路由/懒加载 → UI → store/service → API →
后台任务 → 表/存储对象 → 其他消费者`，覆盖 Web、Electron、Mobile/PWA、Popup、CLI、
内置工具、MCP、分享应用、Workbench、自动化和回调。

每个代码单元标记为：

`DELETE_UI` 专用 UI 删除・`NEST` 下沉・`KEEP_SHARED` 共享能力保留・
`KEEP_COMPAT` 兼容 / 历史读取・`STOP_PRODUCER` 停独立生产流程・
`NEEDS_TRACE` 依赖未确定（**不可直接删**）

**上游已具备的能力，不在 fork 里再实现一份。** 判定归属用
`gh search code "<符号>" --owner lobehub`：0 命中即 fork 原生。若 fork 已经写了平行实现，
删掉它而不是让它与上游并存 —— 同一语义的两条写入路径会让界面自相矛盾。删除前先确认被删的是
fork 那条链路，而不是上游同名机制的消费者。

## 裁决表

「保留」指能力继续存在，不要求原页面结构全部保留。

| 功能域                           | 处理                                               | 保留边界                                                                                                      |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 社区、市场内容展示               | 已退役                                             | MCP 连接、组织内 Agent 配置不能随公共市场一起删；平台自身的技能分发链单独退役，见下                           |
| 独立文稿、写作中心               | 已退役                                             | 任务描述编辑、评论编辑、项目规范、Agent 文档、产物预览不能按 `document/page/editor` 名称批量删除              |
| 独立生图 / 生视频工作台          | 删除产品入口与专用 UI                              | Agent 工具运行、异步回调、生成结果、配额与费用归属、历史产物仍保留                                            |
| 个人身份 / 经历 / 关系画像中心   | 删除独立产品形态                                   | 工作偏好、项目约束、任务状态恢复、已授权的 Agent 上下文与用户数据治理保留                                     |
| 通用评测工作台                   | 退出普通产品构建与导航                             | 任务验收、执行证据、以及被任务链路实际调用的评测实现保留；无任务消费者的通用评测创建 / 导入 / 运行 / 发布退役 |
| 独立 Acceptance / Verify 平台    | 退役独立入口、独立发布与通用流程编辑               | 任务详情内的验收指标、检查、证据、人工审核与完成判定保留；验收对象必须挂在 task /run 下                       |
| 平台 Skill 管理                  | 全链退役，含安装与分发                             | 外部 ACP Agent 自有的技能目录、以及开发仓库自身的 `.agents/skills/*` 指导文档保留                             |
| 自建 OAuth 应用控制台            | 退役                                               | 登录、GitHub / Linear 授权、连接器、设备认证与既有第一方客户端保留                                            |
| 无实现的商业设置页               | 不注册页面                                         | 部署确有实现的订阅 / 用量 / 账单保留；不得以开源默认为空推定线上为空                                          |
| 面向外部访客的可交互共享 Agent   | 停止新的公开发布与访客执行                         | 团队协作、任务链接、邀请审核、受控产物分享保留                                                                |
| 首页大型角色形象、气泡、装饰预设 | 删除                                               | 小头像、Agent 身份显示、执行状态提示保留                                                                      |
| 自动化                           | 并入任务的「周期任务」，**界面名称仍取「自动化」** | 调度、时区、心跳、暂停 / 恢复、立即运行、历史记录和幂等机制保留                                               |
| 资源库                           | 从主导航下沉                                       | 项目资料、任务附件 / 产物、受权限控制的共享资料入口和历史资料读取保留                                         |
| Goal                             | 不再要求用户独立管理一套平行体系                   | 内部长期目标、规划图、依赖和预算保留                                                                          |
| 自我进化 / 成长中心              | 移除成长培养型 UI                                  | 收敛为 Agent 的「规则与经验」，保留来源、版本、启停与可追溯复用                                               |
| 聊天与多 Agent 群聊              | 保留为协作能力，降低导航权重                       | 自由讨论、任务关联会话、多人 / 多 Agent 协作保留                                                              |
| 任务运行中的 steer（追加指令）   | 退回上游机制，删除 fork 自建的服务端平行链路       | 上游 Conversation 层的 `metadata.steer` 链路保留；`submitTaskInput` 服务端多人队列是另一问题，保留            |
| 通知、连接渠道                   | 保留并收敛设置入口                                 | 工作通知、审批回执、任务创建和运行控制保留                                                                    |
| 统计与商业设置                   | 聚焦运行成本和工作结果                             | 额度、成本、用量、账单与审计保留；娱乐化排名、分享海报移除                                                    |

## 隐藏产品面退役的判据

> **任何产品对象都必须有父对象。** 凡是能凭空造出无主对象（没有 task /run/project 归属）的入口，一律退役。

- 退役的是**平行的产品形态**—— 独立验收站点、技能商店、开发者控制台 —— 不是任务执行所需的能力。
- 完成判据不是「导航里没有这个按钮」，而是：从任意入口都无法恢复旧产品，且正式构建不携带其实现。
- 导航不可见**不等于**已退役；只设 `hidden: true` 属于下方「禁止的捷径」。
- 已退役根路径必须保留为保留词，不能被 `/:workspaceSlug` 或 `/agent/:aid/:topicId` 当成业务 ID 解析。
- 平台不得以任何名义（开发工具、内部技能、默认不显示）继续分发已退役的产品面。

## 必须保护的不变量

以下链路不得因功能裁剪而弱化：

- 看板中的同一任务在全局、项目、Agent、「我的任务」中仍是**同一个对象、同一个稳定标识**
- 运行结束**不自动**等于任务验收通过，更不自动等于代码已推送、合并或发布
- 改变看板列不能绕过已存在的完成门控、审批和子任务级联规则
- 已配置的仓库、设备、工作区不可因出错而静默降级到别的执行环境
- 断线、重试、重复回调、迟到回调不得重复创建任务、产物、运行或收费
- 人类负责人和执行 Agent 是不同身份，不相互覆盖
- 权限、工作区隔离、审批、额度、审计、设备身份和访客限制不是「无关功能」

## 已确认的共享依赖（不得按名称批量删除）

| 名称                                   | 为什么必须保留                                                                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `generation*` / `image*` 路由          | `imageGeneration.ts` 通过 `router.createCaller(ctx)` **进程内**调用 generation /generationTopic/image/aiModel/aiProvider，Agent 工具仍在使用 |
| `persona`                              | Agent 每次运行都读它（`operationPrep` → `AgentRuntimeService` → `ContextEngineering`）；退役的只是 `/memory` 的浏览 UI                       |
| `DndContextWrapper`                    | 物理位置在 `ResourceManager` 目录内，但挂在**两个主布局**上，依赖 ResourceManager store 与 tree store                                        |
| 共享编辑器                             | 任务描述、评论、项目规范、Agent 文档、产物预览都在用                                                                                         |
| `/resource/images`、`/resource/videos` | 是**资源库分类**，与生成工作台无关                                                                                                           |

## 禁止的捷径

- 只设 `hidden: true`，旧路由与创建操作照常可达，却宣称功能已删除
- 直接删除 `apps/share`、`ResourceManager`、`generation*`、`memory*`、`document*` 或整个包而没有消费者证据
- 把任务完成列直接映射到「成功」，绕开验收 / 集成状态
- 用新建模拟数据表或 mock 列表替换真正的任务、附件、统计或通知来源
- 为修断链把每个旧链接都重定向 `/tasks` 并丢掉对象 ID
- 把普通成员、Agent、执行操作、外部访客当成同一主体
- 复制源码创建一套「精简版后端」，却让新旧产品同时写同一数据而没有契约
- 对上游已有的能力再写一份 fork 平行实现，使同一语义出现两条写入路径；发现后应删除平行实现，而不是让它与上游并存
- 对所有历史用户强制重置偏好，或仅迁移本地而无视远端旧偏好回写
- 为了对齐某份文档快照而回退更新的代码
