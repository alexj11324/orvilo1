# Production Agent Gateway

The standalone official Go Agent Gateway at `fed50da75b8916566f87e32fafd852a8a34e336b`, with `backend-origin.patch`, runs in a single container, with host port `28787` bound to loopback. Nginx and the proxied Cloudflare hostname expose `https://agent-gateway.aspectlylabs.com` for HTTP and WebSocket clients.

Run `sudo ./build.sh` on the ARM64 origin. It verifies the upstream archive and Go toolchain checksums, applies the backend URL patch, runs `go vet` and race tests, and builds `orvilo-agent-gateway:fed50da75b89-origin-v1`. `build-receipt.json` records the source, patch and binary hashes, image ID and Go version. No app image is built or changed.

API-key login in both WebSocket versions accepts only `LOBE_API_BASE_URL`, set to `https://orvilo.aspectlylabs.com` by the launcher. A missing or invalid configured backend URL fails validation. A trailing slash is equivalent; different schemes, ports or paths are rejected before HTTP. JWT authentication remains unchanged. The added unit tests replace the HTTP transport in memory and make no external requests.

Install `start.sh` below `/var/lib/orvilo1/agent-gateway`, the unit in `/etc/systemd/system`, and `nginx.conf` under `/etc/nginx/sites-available/orvilo-agent-gateway` with the matching enabled symlink. Export only the public RSA JWKS from the current production app into `/etc/orvilo-agent-gateway/jwks.public.json`. Create a root-owned mode-0600 `/etc/orvilo-agent-gateway/config.env` from `config.env.example`, filling in the deployment's private Secret Manager project/reference and authorized host user. These references stay on the host. The unit fetches the credential from Secret Manager and creates root-only environment files in `/run/orvilo-agent-gateway` (tmpfs), then runs the nonroot container.

The additive `app.override.yml` is used after the existing production overrides. Recreate only `orvilo` and `hatchet-worker`, with their original image IDs pinned, no pull and no build. Existing `.env` and Device Gateway configuration are retained. The service must start before Compose reads the tmpfs file. Restarting the service loses in-memory gateway sessions; durable conversation history stays in the app database.

Before changing app configuration, snapshot the current override and image IDs in a root-only rollback directory. `sudo ./activate.sh rollback` restores that override, recreates app and worker with the original image IDs, disables/stops the Agent Gateway unit, removes only its nginx site, and reloads nginx after `nginx -t`. Remove the Agent Gateway DNS record through the same DNS tool used to create it. The Secret Manager secret can remain as an inactive rollback credential.

Acceptance checks: loopback/public `/health` return `OK`; unauthorized `/api/operations/*` returns 401; invalid v2 JWT closes with 4401; the app public global config exposes this URL and Gateway Mode; app and worker share the correct service credential; a normal authenticated app-issued user token opens v2 and receives events from an authenticated operation publication. Record build source, binary/image digest and the app image IDs in the deployment receipt.
