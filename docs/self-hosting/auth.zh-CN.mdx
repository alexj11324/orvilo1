# 身份验证服务

Orvilo 将登录委托给独立的**账户门户**，由 [Clerk](https://clerk.com) 提供支持。门户持有 Clerk 会话；Orvilo 应用将 Clerk 会话令牌交换为自身的 `orvilo_auth` 会话 Cookie，并写入 `auth_sessions` 表。

## 工作原理

1. 未登录用户访问 Orvilo 时被重定向到账户门户（`AUTH_ACCOUNTS_URL`，例如 `https://accounts.aspectlylabs.com`）。
2. 用户在门户中通过 Clerk 登录（邮箱 / 密码、魔法链接、OAuth —— 取决于 Clerk 实例启用的方式）。
3. 登录后门户携带 Clerk 会话令牌调用应用的 `POST /api/auth/clerk` 端点；应用校验令牌签名与签发者，并通过 Clerk Backend API 核对会话和用户，随后签发 `orvilo_auth` Cookie。
4. 桌面端与 CLI 的授权同样经由该门户流程，由 Orvilo 内置的 OIDC Provider（`/oidc/*` 端点）完成。

## 环境变量

| 环境变量                       | 类型 | 说明                                                           |
| -------------------------- | -- | ------------------------------------------------------------ |
| `AUTH_ACCOUNTS_URL`        | 必填 | 账户门户登录页的源地址（例如 `https://accounts.aspectlylabs.com`）。         |
| `CLERK_SECRET_KEY`         | 必填 | Clerk Backend API 密钥（`sk_*`）—— 用于校验会话并在首次登录时创建用户。            |
| `CLERK_ISSUER`             | 可选 | Clerk 签发者 / 前端 API 源地址（例如 `https://clerk.aspectlylabs.com`）。 |
| `CLERK_AUTHORIZED_PARTIES` | 可选 | 会话令牌交换的 `azp` 白名单（逗号分隔）。                                     |
| `CLERK_JWT_KEY`            | 可选 | PEM 公钥，用于完全离线的会话 JWT 校验（跳过 JWKS 拉取）。                         |
| `AUTH_COOKIE_DOMAIN`       | 可选 | 会话 Cookie 的父域名（例如 `.aspectlylabs.com`），使门户与应用共享登录态。          |
| `AUTH_SESSION_TTL_SECONDS` | 可选 | 应用会话有效期（秒），默认 30 天。                                          |

完整参考见 [身份验证环境变量](/docs/self-hosting/environment-variables/auth)。

## 登录方式

邮箱 / 密码、魔法链接、OAuth 提供商与 MFA 均在账户门户对应的 Clerk 控制台中配置 —— 不再使用 Orvilo 环境变量。转发给门户的特性开关：

| 环境变量                          | 说明                 |
| ----------------------------- | ------------------ |
| `AUTH_DISABLE_EMAIL_PASSWORD` | 在门户登录页隐藏邮箱 / 密码表单。 |
| `AUTH_ENABLE_MAGIC_LINK`      | 在门户启用魔法链接登录。       |
| `AUTH_EMAIL_VERIFICATION`     | 在门户要求邮箱验证。         |

## 旧版说明

- Orvilo 早期版本使用 Better Auth。该库及其 `/api/auth/*` 端点已移除；Better Auth 签发的会话（`<prefix>.session_token` Cookie）在过期前仍然有效，过期后用户需通过门户重新登录。
- Better Auth 时代的数据表（`account`、`auth_sessions` 旧行等）保留用于数据留存。
