## 4. 待运行时验证项

1. **V1 卡首行语义复核**：`COMPONENT_SPEC.md` 写「first-line comment excerpt」，实现与 `rich-preview-verification.md` 采用「issue 名」。下次接触参考端时对一张卡做只读 DOM 取证（首行文本是否等于 issue 名），一次定论；若实为草稿摘录，则 `taskName` 标题与 D15 的 identifier chip 需一起改。
2. **Discard 完成态**：在合成工作区里点完确认框，验列表空 + 角标归零（上次被工具审查拦下，需要用明确授权的合成草稿重跑）。
3. **Discard all**：两条草稿场景下验全清 + 角标。
4. **富内容卡在 Electron**：造含 mention/issue link chip、`local-file-tag`、附件节点的真草稿，验预览渲染与整卡点击不被内层链接截获（`inert` 已设，需实测）。
5. **卡高 144.4 vs 139**（D4）：决定是收 `preview`/`excerpt` 尺寸还是接受；若收，改动后重新量 1440×900 与 1729 宽两档。
6. **`?draft=1` 去留**（D6）：若要对齐参考端 URL，可把 scroll+focus 触发改为「草稿存在且来自 Drafts 入口」的导航 state；当前实现简单且功能等价，属于可接受的已知差。
7. **参考端空态 / 确认流**：仍是未观测面 —— 参考端 `Discard all`/ 单卡 discard 是否有确认、空态文案均未知；候选端确认流是保守外推，回采前不改。
8. **并发边角**：在任务页有 pending autosave 时立刻回 Drafts 丢弃 ——`queueSave` 的 in-flight upsert 与 discard 的 delete 无显式串行，理论上有「删后又被回写」的时序窗；如需收紧可在 delete 前让服务端按 `updatedAt` 或直接由 drafts 页调 discard 专用端点。当前单会话顺序操作下风险低，记录备查。
9. **`deleteAll` 语义**（D13）：若产品口径是「清掉我所有草稿」而非「可见的」，需改 model；当前实现与角标口径一致（角标也只数可见）。
10. 暗色主题、390px、hover 态、`electron-drafts-populated.png` 对应的新版卡形态补拍。
