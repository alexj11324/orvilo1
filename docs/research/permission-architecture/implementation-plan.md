### Maintained backfill CLI

`scripts/backfillWorkspacePermissions.ts` takes `--workspace=ID --plan=reviewed.json` and defaults to dry run. JSON has `workspaceId` and at most 1000 exact reviewed `entries`; no discovery or wildcard apply. Each entry pins `kind`, `resourceId`, `ownerId`, `visibility` and active workspace `member: {role, authzVersion}`. Permission entries also pin `userId` and expected existing grant/membership (`null` means reviewed absence), plus stable target UUIDs for inserts. Agent entries: `kind: agent-use`, `expectedGrant: {id, level} | null`, `targetGrantId`. Creator manager: `kind: project-manager`, `expectedMembership: {id, role, authzVersion} | null`, `targetMembershipId`. Commenter/viewer: `kind: project-participant` with exact existing membership. Inactive membership always rejects; global Agent rows cannot enter per-user conversion.

Publication uses a separate plan containing only `publish-agent`/`publish-project`, explicit `--operation=publication`, and expected private visibility. Owner membership is checked; direct visibility updates preserve grants. Permissions plans cannot publish. `--apply` is an explicit operator action after reviewed scope approval; no startup hook. Apply validates under row locks in a bounded serializable transaction and rolls back on drift; exact resulting states permit idempotent reruns. Startup never restores a cancelled grant. Apply additionally requires `--receipt=PATH`: an atomic exclusive-create file at mode 0600, binding workspace, operation, plan digest and target IDs, is claimed before BEGIN. A consumed plan permits only exact resulting-state no-ops; missing or downgraded grants, scope or visibility drift reject replay and require fresh preview/approval. Failed or unknown applies conservatively retain the receipt; no retries/recovery system.

Native CLI dry run on the owned isolated fixture: `apply=false`, 12 proposed changes (11 creator Use, 1 absent creator manager); metadata comparison before/after equal. No apply. Temporary plan excludes inactive existing creator row and has no publication entries. `/private/tmp/orvilo-permission-architecture/permission-dryrun-plan.json`, `permission-cli-dryrun.log`. Seven PGlite SQL regressions cover dry run, idempotence, per-user conversion/global exclusion, inactive preservation/atomic rollback, scope/owner/member/grant drift, and separate publication preserving grants.
