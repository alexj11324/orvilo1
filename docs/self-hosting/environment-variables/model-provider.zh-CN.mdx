# 模型服务商

Orvilo 在部署时提供了丰富的模型服务商相关的环境变量，你可以使用这些环境变量轻松定义需要在 Orvilo 中开启的模型服务商。

## OpenAI

### `ENABLED_OPENAI`

- 类型：可选
- 描述：默认启用 OpenAI 作为模型供应商，当设为 0 时关闭 OpenAI 服务
- 默认值：`1`
- 示例：`0`

### `OPENAI_API_KEY`

- 类型：必选
- 描述：这是你在 OpenAI 账户页面申请的 API 密钥，可以前往 [这里](https://platform.openai.com/api-keys) 查看
- 默认值：-
- 示例：`sk-xxxxxx...xxxxxx`

### `OPENAI_PROXY_URL`

- 类型：可选
- 描述：如果你手动配置了 OpenAI 接口代理，可以使用此配置项来覆盖默认的 OpenAI API 请求基础 URL
- 默认值：`https://api.openai.com/v1`
- 示例：`https://api.chatanywhere.cn` 或 `https://aihubmix.com/v1`

<Callout type={'warning'}>
  请检查你的代理服务商的请求后缀，有的代理服务商会在请求后缀添加
  `/v1`，有的则不会。如果你在测试时发现 AI 返回的消息为空，请尝试添加 `/v1` 后缀后重试。
</Callout>

<Callout type={'info'}>
  是否填写 `/v1` 跟模型服务商有很大关系，比如 openai 的默认地址是 `api.openai.com/v1`
  。如果你的代理商转发了 `/v1` 这个接口，那么直接填 `proxy.com` 即可。 但如果模型服务商是直接转发了
  `api.openai.com` 域名，那么你就要自己加上 `/v1` 这个 url。
</Callout>

### `OPENAI_MODEL_LIST`

- 类型：可选
- 描述：用来控制模型列表，使用 `+` 增加一个模型，使用 `-` 来隐藏一个模型，使用 `模型名=展示名<扩展配置>` 来自定义模型的展示名，用英文逗号隔开。模型定义语法规则见 [模型列表][model-list]
- 默认值：`-`
- 示例：`+qwen-7b-chat,+glm-6b,-gpt-3.5-turbo,gpt-4-turbo=gpt-4o`

上面示例表示增加 `qwen-7b-chat` 和 `glm-6b` 到模型列表，而从列表中删除 `gpt-3.5-turbo`，并将 `gpt-4-turbo` 模型名字展示为 `gpt-4o`。如果你想先禁用所有模型，再启用指定模型，可以使用 `-all,+gpt-3.5-turbo`，则表示仅启用 `gpt-3.5-turbo`。

你可以在 [modelProviders](https://github.com/alexj11324/orvilo1/tree/main/packages/model-bank/src/modelProviders) 查找到当前的所有模型名。

## Meta

连接官方 [Meta Model API](https://dev.meta.ai/)，设置步骤见[在 Orvilo 中使用 Meta](/zh/docs/usage/providers/meta)。

### `META_API_KEY`

- 类型：部署时可选；提供共享服务端密钥时必填。用户也可以在 Meta 服务商设置中填写自己的密钥。
- 描述：在 [Model API 控制台](https://dev.meta.ai/) 创建的密钥。设置非空密钥后，服务端配置会自动启用 Meta。`ENABLED_META` 由此密钥派生，不是独立的环境变量开关。Orvilo 使用 `META_API_KEY`，与 Meta SDK 示例中的 `MODEL_API_KEY` 名称不同。
- 默认值：未设置，不提供共享服务端密钥。
- 示例：`your-meta-model-api-key`

### `META_PROXY_URL`

- 类型：可选
- 描述：覆盖 Meta API 基础地址。代理必须支持 Responses API。请填写基础地址，而非完整的 `/responses` 接口地址。
- 默认值：`https://api.meta.ai/v1`
- 示例：`https://meta-proxy.example.com/v1`

### `META_MODEL_LIST`

- 类型：可选
- 描述：使用通用[模型列表语法][model-list]自定义模型列表：`+` 增加模型，`-` 隐藏模型，`模型 ID=展示名` 修改展示名称，各项用英文逗号分隔。此配置不会授予 Meta 账户尚未拥有的模型访问权限。
- 默认值：未设置，使用内置模型列表。
- 示例：`-all,+muse-spark-1.3`

上例隐藏所有默认模型，再添加 `muse-spark-1.3`。版本信息请参阅 [Muse Spark 产品页](https://developer.meta.com/ai/models/muse-spark/)和 Meta 的 [Muse Spark 1.3 发布公告](https://www.threads.com/@metafordevelopers/post/Dcy9DWLmfVn)，模型可用性以账户的 API 访问权限为准。

## Azure OpenAI

如果你需要使用 Azure OpenAI 来提供模型服务，可以查阅 [使用 Azure OpenAI 部署](/zh/docs/self-hosting/examples/azure-openai) 章节查看详细步骤，这里将列举和 Azure OpenAI 相关的环境变量。

### `AZURE_API_KEY`

- 类型：必选
- 描述：这是你在 Azure OpenAI 账户页面申请的 API 密钥
- 默认值：-
- 示例：`c55168be3874490ef0565d9779ecd5a6`

### `AZURE_ENDPOINT`

- 类型：必选
- 描述：Azure API 地址，从 Azure 门户检查资源时，可在 “密钥和终结点” 部分中找到此值
- 默认值：`-`
- 示例：`https://docs-test-001.openai.azure.com`

### `AZURE_API_VERSION`

- 类型：必选
- 描述：Azure 的 API 版本，遵循 YYYY-MM-DD 格式
- 默认值：`-`
- 示例：`2024-02-01`，查阅 [最新版本](https://docs.microsoft.com/zh-cn/azure/developer/javascript/api-reference/es-modules/azure-sdk/ai-translation/translationconfiguration?view=azure-node-latest#api-version)

### `AZURE_MODEL_LIST`

- 类型：必选
- 描述：用来控制模型列表，使用 `模型名->部署名=展示名` 来自定义模型的展示名，用英文逗号隔开。支持扩展能力，其余语法规则详见 [模型列表][model-list]
- 默认值：`-`
- 示例：`gpt-35-turbo->my-deploy=GPT 3.5 Turbo` 或 `gpt-4-turbo->my-gpt4=GPT 4 Turbo<128000:vision:fc>`

## Vertex AI

### `VERTEXAI_CREDENTIALS`

- 类型：必选
- 描述：Google Cloud 服务账号密钥的 JSON 字符串。用于认证和授权访问 Vertex AI 服务，获取方法请参考 [这里](/zh/docs/usage/providers/vertexai)
- 默认值：-
- 示例：`{"type": "service_account", "project_id": "your-gcp-project-id", ...}`

### `VERTEXAI_PROJECT`

- 类型：可选
- 描述：你的 Google Cloud 项目 ID。如果未设置，将从 `VERTEXAI_CREDENTIALS` 中的 `project_id` 字段获取。
- 默认值：-
- 示例：`your-gcp-project-id`

### `VERTEXAI_LOCATION`

- 类型：可选
- 描述：你的 Vertex AI 模型所在的区域。
- 默认值：`global`
- 示例：`us-central1`

## NewAPI

### `NEWAPI_API_KEY`

- 类型：可选
- 描述：这是你的 NewAPI 服务实例的 API 密钥。NewAPI 是一个多供应商模型聚合服务，提供对各种 AI 模型 API 的统一访问。
- 默认值：-
- 示例：`sk-xxxxxx...xxxxxx`

### `NEWAPI_PROXY_URL`

- 类型：可选
- 描述：你的 NewAPI 服务器实例的基础 URL。这应该指向你部署的 NewAPI 服务端点。
- 默认值：-
- 示例：`https://your-newapi-server.com`

<Callout type={'info'}>
  NewAPI
  是一个多供应商模型聚合服务，支持基于供应商检测的自动模型路由。它提供成本管理功能，并为访问包括
  OpenAI、Anthropic、Google 等多个供应商的模型提供单一端点。了解更多关于 NewAPI 的信息请访问
  [https://github.com/Calcium-Ion/new-api](https://github.com/Calcium-Ion/new-api)。
</Callout>

## Unsloth

连接你自己的 Unsloth Studio 实例。浏览器认证和桌面版 CORS 限制请参阅[在 Orvilo 中使用 Unsloth](/zh/docs/usage/providers/unsloth)。

### `UNSLOTH_API_KEY`

- 类型：部署时可选；提供需要认证的共享服务端访问时，应填写真实的 Studio 密钥。用户也可以在服务商设置中自行配置密钥。
- 描述：你的 Studio 实例的 API 密钥。非空值会在服务端配置中启用此服务商。`ENABLED_UNSLOTH` 由密钥派生，不是独立的环境变量开关。本地服务端无密钥访问取决于 Studio 的访问策略；跨来源浏览器请求需要有效认证。
- 默认值：未设置，不提供共享服务端密钥。
- 示例：`your-unsloth-studio-api-key`

### `UNSLOTH_PROXY_URL`

- 类型：可选
- 描述：覆盖 OpenAI 兼容 API 的基础地址。请填写 Orvilo 服务器可访问的地址。在 Docker 内，`127.0.0.1` 指容器自身，不是运行 Studio 的宿主机。若启动 Studio 时明确指定端口，请使用该端口替代默认的 `8888`。
- 默认值：`http://127.0.0.1:8888/v1`
- 示例：`http://studio.example.com:8888/v1`

### `UNSLOTH_MODEL_LIST`

- 类型：可选
- 描述：使用共享的[模型列表语法][model-list]配置模型列表：`+` 增加模型，`-` 隐藏模型，`模型ID=显示名称` 重命名模型，多个条目用英文逗号分隔。请使用 Studio 实例返回的模型 ID；此配置不会下载模型。
- 默认值：未设置，使用内置示例模型列表，示例默认不启用；不保证这些模型已在本地安装，也不会改变已有的模型选择。
- 示例：`-all,+your-local-model-id=Local Model`

[model-list]: /zh/docs/self-hosting/advanced/model-list
