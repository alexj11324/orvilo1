# 身份验证服务

Orvilo 将登录委托给由 Clerk 提供支持的账户门户。以下环境变量用于配置应用与 Clerk 的交互以及会话 Cookie 的签发方式。

## 账户门户与会话

#### `AUTH_ACCOUNTS_URL`

- 类型：必填
- 说明：账户门户的源地址，承载 Clerk 登录。未认证的请求会跳转到 `${AUTH_ACCOUNTS_URL}/login?return_url=…`。
- 默认值：`https://accounts.aspectlylabs.com`
- 示例：`https://accounts.example.com`

#### `AUTH_COOKIE_DOMAIN`

- 类型：可选
- 说明：`orvilo_auth` 会话 Cookie 的父域名，使门户交换可以落到同级子域名。不设置则为仅当前域名可用（本地开发）。
- 默认值：`-`
- 示例：`.aspectlylabs.com`

#### `AUTH_COOKIE_PREFIX`

- 类型：可选
- 说明：迁移窗口内仍会读取的旧版 Better Auth Cookie 命名空间（`<prefix>.session_token`）。对新的 `orvilo_auth` Cookie 无影响。
- 默认值：`better-auth`
- 示例：`my-orvilo`

#### `AUTH_SESSION_TTL_SECONDS`

- 类型：可选
- 说明：应用签发的会话（`auth_sessions` 行）有效期，单位秒。会话过半后活动会顺延过期时间。
- 默认值：`2592000`（30 天）
- 示例：`604800`

#### `AUTH_DISABLE_EMAIL_PASSWORD`

- 类型：可选
- 说明：设为 `1` 时在门户登录页隐藏邮箱 / 密码表单。
- 默认值：`0`
- 示例：`1`

#### `AUTH_EMAIL_VERIFICATION`

- 类型：可选
- 说明：设为 `1` 时在门户要求邮箱验证。
- 默认值：`0`
- 示例：`1`

#### `AUTH_ENABLE_MAGIC_LINK`

- 类型：可选
- 说明：设为 `1` 时在门户启用魔法链接登录。
- 默认值：`0`
- 示例：`1`

## Clerk

#### `CLERK_SECRET_KEY`

- 类型：必填
- 说明：Clerk Backend API 密钥（`sk_*`）。`POST /api/auth/clerk` 依赖它确认会话有效并获取 / 创建用户记录。
- 默认值：`-`
- 示例：`sk_live_xxxxxxxxxxxxxxxx`

#### `CLERK_ISSUER`

- 类型：可选
- 说明：Clerk 签发者，即 Clerk 实例的前端 API 源地址（同时作为 JWKS 基础地址）。不设置时默认生产 Clerk 地址。
- 默认值：`https://clerk.aspectlylabs.com`
- 示例：`https://clerk.example.com`

#### `CLERK_AUTHORIZED_PARTIES`

- 类型：可选
- 说明：会话令牌交换时校验的 `azp`（授权方）白名单，逗号分隔。
- 默认值：`-`
- 示例：`https://accounts.aspectlylabs.com`

#### `CLERK_JWT_KEY`

- 类型：可选
- 说明：PEM 编码的 RS256 公钥。设置后会话 JWT 在本地校验，无需向签发者拉取 JWKS。
- 默认值：`-`

#### `CLERK_API_URL`

- 类型：可选
- 说明：Clerk Backend API 基础地址覆盖（仅用于测试 / 代理）。
- 默认值：`https://api.clerk.com`

## 内部 JWT

#### `JWKS_KEY`

- 类型：必填
- 说明：用于签发和验证 JWT 的 JWKS（JSON Web Key Set）密钥。供内置 OIDC Provider（桌面端 / CLI 授权）与内部服务调用认证使用。必须是包含 RS256 RSA 密钥对的 JWKS JSON 字符串。

#### `INTERNAL_JWT_EXPIRATION`

- 类型：可选
- 说明：lambda → async 内部调用的 JWT 过期时间，格式 `<数字><单位>`（`s`、`m`、`h`）。
- 默认值：`30s`
- 示例：`1m`

## Webhooks

#### `CASDOOR_WEBHOOK_SECRET`

- 类型：可选
- 说明：校验 Casdoor 用户同步 Webhook 的共享密钥（仅旧版部署）。
- 默认值：`-`

#### `LOGTO_WEBHOOK_SIGNING_KEY`

- 类型：可选
- 说明：校验 Logto 用户同步 Webhook 的签名密钥（仅旧版部署）。
- 默认值：`-`

## 邮件服务

事务性邮件（工作区邀请、通知）支持两种发送方式：Nodemailer SMTP（默认）和 Resend。

#### `EMAIL_SERVICE_PROVIDER`

- 类型：可选
- 说明：`nodemailer`（默认）或 `resend`。
- 默认值：`nodemailer`
- 示例：`resend`

#### `SMTP_HOST`

- 类型：`nodemailer` 时必填
- 说明：SMTP 服务器主机名。
- 示例：`smtp.gmail.com`

#### `SMTP_PORT`

- 类型：可选
- 说明：SMTP 服务器端口。TLS 通常为 `587`，SSL 为 `465`。

#### `SMTP_SECURE`

- 类型：可选
- 说明：设为 `true` 使用 SSL。
- 默认值：`false`

#### `SMTP_USER`

- 类型：可选
- 说明：SMTP 认证用户名，通常为你的邮箱地址。

#### `SMTP_PASS`

- 类型：可选
- 说明：SMTP 认证密码或应用专用密码。

#### `SMTP_FROM`

- 类型：可选
- 说明：SMTP 外发邮件的发件人地址。

#### `RESEND_API_KEY`

- 类型：`resend` 时必填
- 说明：Resend API 密钥。

#### `RESEND_FROM`

- 类型：可选
- 说明：Resend 外发邮件的发件人地址。
