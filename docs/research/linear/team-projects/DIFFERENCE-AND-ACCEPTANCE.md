## Data contract and integration dependency

`TeamPage.tsx` already queries `workAttention.query` with `entityType: 'project'` and a `teamId eq` predicate. `WorkQueryModel.queryProjects()` applies readability restrictions and returns raw project rows plus `total` and `queryHash`; an existing integration test verifies that a project linked to two teams appears in both team queries. Raw project rows carry the core attributes for Name, Health, Priority, Lead, Target date, and Status, but no `taskCount` or `progressPercent`. `ProjectModel.list()` computes both values from readable project tasks for the workspace table. Passing the existing team-query rows straight to the workspace row would display missing Issues/progress values. The team-scoped presentation therefore needs a real enriched projection or a verified join with the workspace list. The current team query is limited to 50 rows and has a cursor protocol; accepting only the first page needs a deliberate scale decision.

The workspace table implementation in `src/features/Projects/List/index.tsx` and the team host in `src/features/WorkTeams/TeamPage.tsx` are both owned by other active slices. No integration edits are made here until those owners publish a stable shared table boundary. A minimal handoff is: export one presentation from the workspace list, feed it readable team-filtered projects with real count/progress, then replace only the Team Projects branch and add its header/toolbar. Preserve its existing loading, empty, inline error/retry, and project navigation outcomes.
