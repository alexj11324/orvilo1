# Authentication Service

Orvilo delegates sign-in to a Clerk-powered accounts portal. The variables below configure how the app talks to Clerk and how it issues its own session cookie.

## Accounts Portal & Session

#### `AUTH_ACCOUNTS_URL`

- Type: Required
- Description: Origin of the accounts portal that hosts Clerk sign-in. Unauthenticated requests to the app bounce to `${AUTH_ACCOUNTS_URL}/login?return_url=…`.
- Default: `https://accounts.aspectlylabs.com`
- Example: `https://accounts.example.com`

#### `AUTH_COOKIE_DOMAIN`

- Type: Optional
- Description: Parent domain set on the `orvilo_auth` session cookie so the portal exchange can land on sibling subdomains. Omit for host-only cookies (local development).
- Default: `-`
- Example: `.aspectlylabs.com`

#### `AUTH_COOKIE_PREFIX`

- Type: Optional
- Description: Namespace of the legacy Better Auth cookie (`<prefix>.session_token`) that is still read during the migration window. Has no effect on the new `orvilo_auth` cookie.
- Default: `better-auth`
- Example: `my-orvilo`

#### `AUTH_SESSION_TTL_SECONDS`

- Type: Optional
- Description: Lifetime of the app-issued session (`auth_sessions` rows) in seconds. Past half the TTL, activity refreshes the expiry.
- Default: `2592000` (30 days)
- Example: `604800`

#### `AUTH_DISABLE_EMAIL_PASSWORD`

- Type: Optional
- Description: Set to `1` to hide the email/password form on the portal sign-in page.
- Default: `0`
- Example: `1`

#### `AUTH_EMAIL_VERIFICATION`

- Type: Optional
- Description: Set to `1` to require email verification on the portal.
- Default: `0`
- Example: `1`

#### `AUTH_ENABLE_MAGIC_LINK`

- Type: Optional
- Description: Set to `1` to enable magic-link sign-in on the portal.
- Default: `0`
- Example: `1`

## Clerk

#### `CLERK_SECRET_KEY`

- Type: Required
- Description: Clerk Backend API secret key (`sk_*`). Required by `POST /api/auth/clerk` to confirm the session is active and to fetch/provision the user record.
- Default: `-`
- Example: `sk_live_xxxxxxxxxxxxxxxx`

#### `CLERK_ISSUER`

- Type: Optional
- Description: Clerk issuer — the frontend API origin of your Clerk instance (also used as the JWKS base). Defaults to the production clerk host when unset.
- Default: `https://clerk.aspectlylabs.com`
- Example: `https://clerk.example.com`

#### `CLERK_AUTHORIZED_PARTIES`

- Type: Optional
- Description: Comma-separated `azp` (authorized parties) allowlist checked during session-token exchange.
- Default: `-`
- Example: `https://accounts.aspectlylabs.com`

#### `CLERK_JWT_KEY`

- Type: Optional
- Description: PEM-encoded RS256 public key. When set, session JWTs are verified locally without fetching JWKS from the issuer.
- Default: `-`

#### `CLERK_API_URL`

- Type: Optional
- Description: Clerk Backend API base URL override (testing/proxy only).
- Default: `https://api.clerk.com`

## Internal JWTs

#### `JWKS_KEY`

- Type: Required
- Description: JWKS (JSON Web Key Set) key for signing and verifying JWTs. Used for the built-in OIDC provider (desktop/CLI authorization) and internal service call authentication. Must be a JWKS JSON string containing an RS256 RSA key pair.

#### `INTERNAL_JWT_EXPIRATION`

- Type: Optional
- Description: Internal JWT expiration for lambda → async calls, format `<number><unit>` (`s`, `m`, `h`).
- Default: `30s`
- Example: `1m`

## Webhooks

#### `CASDOOR_WEBHOOK_SECRET`

- Type: Optional
- Description: Shared secret for verifying Casdoor user-sync webhooks (legacy deployments only).
- Default: `-`

#### `LOGTO_WEBHOOK_SIGNING_KEY`

- Type: Optional
- Description: Signing key for verifying Logto user-sync webhooks (legacy deployments only).
- Default: `-`

## Email Service

Transactional email (workspace invitations, notifications) supports two providers: SMTP via Nodemailer (default) and Resend.

#### `EMAIL_SERVICE_PROVIDER`

- Type: Optional
- Description: `nodemailer` (default) or `resend`.
- Default: `nodemailer`
- Example: `resend`

#### `SMTP_HOST`

- Type: Required (for `nodemailer`)
- Description: SMTP server hostname.
- Example: `smtp.gmail.com`

#### `SMTP_PORT`

- Type: Optional
- Description: SMTP server port. Usually `587` for TLS or `465` for SSL.

#### `SMTP_SECURE`

- Type: Optional
- Description: Set to `true` to use SSL.
- Default: `false`

#### `SMTP_USER`

- Type: Optional
- Description: SMTP authentication username, usually your email address.

#### `SMTP_PASS`

- Type: Optional
- Description: SMTP authentication password or app-specific password.

#### `SMTP_FROM`

- Type: Optional
- Description: Sender address for outgoing SMTP mail.

#### `RESEND_API_KEY`

- Type: Required (for `resend`)
- Description: Resend API key.

#### `RESEND_FROM`

- Type: Optional
- Description: Sender address for Resend mail.
