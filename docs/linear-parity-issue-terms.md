# task → issue terminology unification

Part of the strict two-way Linear parity track: Linear calls the tracked unit of
work an **issue**; Orvilo's UI called it a **task**. This change renames the
user-facing copy to "issue" everywhere the word refers to that entity —
nav/tabs ("Tasks" → "Issues"), task detail labels, lists, menus, dialogs,
placeholders, notifications, search keywords — across the default locale source
(`packages/locales/src/default/*.ts`), `locales/en-US/` and a hand pass of
`locales/zh-CN/` (任务 → 问题).

Internal identifiers are intentionally unchanged: i18n keys (`taskDetail.*`,
`task.status.*`), route paths, API fields and code symbols still say "task".
Only rendered strings moved.

## Decision rule used per string

**Renamed** — "task" naming the issue-tracker entity or things attached to it:
lists/boards/detail pages, prerequisites, sub-tasks (→ "Sub-issues", Linear's
spelling), status labels, assignee/visibility copy, goal/task-tree references,
task templates, Orvilo's own issue-CRUD tool descriptions
(`orvilo-task`, `orvilo-claude-code.task.*` inspector labels), placeholders,
notification text, cmdk keywords, `Issue Manager`.

**Kept** — "task" naming an agent-runtime concept or an external product name:

- Literal tool names shown in agent activity (`builtins.claude-code.apiName.Task*`,
  Codex `todo_list`, `orvilo-*-management.apiName.*`, `inspectTask`,
  `executeAgentTask`) — renaming would mislabel the actual tool.
- Agent todo lists and batch/parallel fan-out (`todoProgress`, `*.todos.*`,
  `task.batchTasks`, `task.groupTasks*`, `task.subtask` chip,
  `task.intermediateSteps`, `task.metrics.*`, `task.activity.*`,
  `taskCallback.*`).
- Scheduled agent jobs (`agentCronJobs.*`, cron notifications, `Scheduled tasks`
  dashboard widgets) — a cron job is not an issue.
- Background/infra jobs (`claudeSdkRuntime` background tasks,
  `orvilo-local-system` shell background tasks, workflow task internals).
- Model/runtime generic usage (`extendParams.*` "complex tasks", eval/ragEval).
- Third-party catalog copy (Composio server descriptions, MCP/skills category
  names like "Task Management").

Grammar: "a task" → "an issue" handled wholesale; `{{taskId}}` interpolation
parameters untouched.

zh-CN: 任务 → 问题 in renamed keys only; runtime/cron/todo strings kept as 任务.
Remaining locales are regenerated by the daily `auto-i18n` workflow.
